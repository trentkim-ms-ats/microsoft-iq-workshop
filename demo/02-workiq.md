# 발표자 데모 02 — WorkIQ: 권한을 지키는 업무 근거

## 목적과 실행 경계

발표자가 샘플 M365 콘텐츠를 검색해 **왜 그런 일이 논의됐는지**의 내부 업무
맥락을 보여줍니다. WorkIQ는 ACL(접근 제어)에 따라 Outlook, Teams,
SharePoint, OneDrive 근거를 찾습니다. 정형 KPI는 Track1 FabricIQ에서,
공개 웹의 최신 근거는 Track3 WebIQ에서 가져옵니다. 문서의 진술만으로 수치를
역산하거나 인과관계를 확정하지 않습니다.

아래 live 검색·계정 전환·배포는 **사람이 별도 승인한 샘플/격리 테넌트에서만**
발표자가 수행합니다. 실제 직원 데이터와 운영 사이트는 사용하지 않습니다.
승인이나 접속이 없으면 승인된 샘플 캡처 또는 로컬 manifest를 보여주되
`기록 화면`/`정적 샘플, live 미검증`으로 명시합니다. dry-run은 실행 계획,
simulation은 재현용 결과이며 어느 쪽도 live 검색·ACL·메일 배송 증거가 아닙니다.

## 기존 미션 전체 → 발표자 데모

기존 Track2 일정 **110분(25+25+35+25)**과 게이트는 바뀌지 않습니다.

| 미션 | 발표자가 보여줄 화면과 설명 | 결과 |
|---|---|---|
| 1 킥오프·인벤토리 | Track1 인계 6범주, 고정 키워드 5개, 4개 소스 | 킥오프 로그·인덱스 카탈로그 |
| 2 교차 매핑 | 같은 엔터티의 서로 다른 소스 문서와 표기 차이 | 엔터티-문서 매핑표 |
| 3 품질 | 8개 항목별 원본·검증 근거 | 증적 수집표 |
| 4 점수·인계 | 점수와 미달 조치, Track3 입력 | 품질 리포트·WebIQ 인계 |

## 발표 전 준비

1. [Track1 인계](01-fabriciq.md)를 받아 Workspace/Ontology 식별 정보, 모델
   개수와 경로 3개, 매핑 5개 이상, 제한·우회안, 검색 키, 매핑/SQL/선택 Graph
   로그의 **6개 범주**를 검수합니다. 빠졌으면 Track1 담당자에게 반환하고
   `blockingIssue`에 기록합니다. P1 오류 탐지 결과는 요구하지 않습니다.
2. 승인된 샘플 계정 2개(발표자가 사용할 참가자 역할과 제한 검증 역할), 4개
   소스의 권한, WorkIQ 커넥터/검색 화면, 색인 범위와 갱신 상태를 관리자와
   확인합니다. ACL은 배포 스크립트가 자동으로 설정하지 않습니다. 권한은 최소화하고
   종료 후 회수합니다. 계정 간 차이를 증명하려면 검색 결과뿐 아니라 원본 열기도
   각각 확인합니다.
3. 정상 시드는 **19건**: SharePoint 6, Outlook 5, Teams 5, OneDrive 3입니다.
   확장 패키지는 **60개 업무 항목**: SharePoint 15, Outlook 15, Teams
   18스레드(총 55메시지), OneDrive 12입니다. 55메시지는 60에 추가하지 않습니다.
   본문에 정확한 엔터티명과 상황·영향·결정·후속 조치 중 최소 2개가 있어야 합니다.
   배포 및 색인에는 시간이 걸리므로 D-1에 준비합니다.
   [시드 명세](../track1/docs/Track1_WorkIQ_Seed_Content_Specification.md)와
   [샘플 패키지](../track2/data/README.md)를 확인합니다.
4. 샘플 준비가 불가능하면 15건 축소 fallback을 사용할 수 있지만 각 소스 1건,
   고정 키워드 5개 중 4개 이상, 핵심 상품 3개 각각 2건 이상을 유지합니다.
   누락·영향을 기록하고 **정상 준비 완료로 판정하지 않습니다**.
5. 시크릿·토큰·계정 식별자·내부 URL을 문서, 화면 캡처, 저장소에 넣지 않습니다.
   승인된 증적 저장소에는 접근 권한과 보존 기간을 적용합니다. 이메일 배송 검증은
   [배송 검증 안내](../track2/data/EMAIL_DELIVERY_VERIFICATION.md)를 따릅니다.

### 준비와 dry-run은 live가 아닙니다

Track2 생성기는 `track2/data/generated/` 전체를 삭제 후 재생성합니다.
기존 산출물의 소유자와 보존 여부를 확인하고 승인된 별도 작업 공간을 사용하세요.
생성·설치나 클라우드 쓰기를 이 문서에서 자동 실행하지 않습니다.

승인된 로컬 패키지와 비밀 없는 설정이 이미 준비된 경우에만 저장소 루트에서
다음 **선택적 dry-run**을 할 수 있습니다. 실제로 실행하기 전 경로와 설정을
검토합니다. 설정에는 `sharePoint`, `oneDrive`, `outlook.senders`/
`recipients`, `teams.channels`가 필요합니다.
상세 키는 [현재 배포 계약](../track2/data/TRACK2_M365_Complete_Deployment_Guide.md)을
따릅니다.

dry-run도 사이트·계정·채널 식별자를 출력할 수 있습니다. **화면 공유를 중지**
하거나 승인된 방식으로 출력을 가리고, 로그의 식별자는 조직 정책에 따라 접근을
제한하고 정리합니다.

```bash
python3 track2/data/deploy_m365_samples.py --config track2/data/deployment_config.json
```

`--execute` 없이 계획만 출력하며 Graph에 쓰지 않습니다. 생성 manifest는 배포·색인
증거가 아닙니다. 실제 배포는 별도 승인된 운영 절차로만 수행합니다.
Outlook의 EML, dry-run, HTTP 수락 또는 Sent Items만으로 수신 배송을 입증할 수
없습니다. 승인 후 참가자 사서함 관찰 또는 테넌트 메시지 추적으로 확인되지 않았다면
`PENDING`/`NOT VERIFIED`로 표시합니다. 무작정 재전송하지 말고 관리자에게
추적 기간과 정책을 확인합니다.

## 발표 진행

### 미션 1 — 인계 확인과 검색 (25분)

1. 승인된 참가자 역할 계정으로 제공된 WorkIQ 검색/커넥터 화면을 엽니다.
   Track1 인계의 6개 범주를 보여주되 실제 식별자와 내부 증적 주소는 가립니다.
2. 검색창에 아래 단어를 **하나씩** 입력하고 소스·제목·시각을 기록한 다음
   결과에서 원본을 엽니다. 결과에 표시된 소스 필터로 각 소스를 점검합니다.
   UI는 테넌트/제품 버전에 따라 다를 수 있습니다. 원본 열기 전 화면 공유를
   중지하거나 브라우저 주소 표시줄과 내부 URL을 승인된 방식으로 가립니다.

| 검색어 | 먼저 기대할 소스 |
|---|---|
| `SummerPush` | SharePoint, Outlook |
| `VIPRetention` | Outlook, SharePoint |
| `AeroPhone X` | Teams, Outlook |
| `SmartWatch Pro` | Teams |
| `Platinum` | Outlook, OneDrive |

3. 공백·대소문자·별칭을 정규화해 실패 검색을 재시도하고 그 결과를 기록합니다.
   최종 5개 중 **4개 이상** 성공해야 합니다. 4개 소스에서 각각 최소 한 건을
   검색하고 열어 카탈로그에 범위(사이트/폴더/채널/메일함), 필터, 마지막 갱신
   시각(KST), 색인 건수 추정과 제한을 기록합니다.
4. 같은 샘플 키워드와 지정된 제한 콘텐츠로 제한 검증 계정에 전환해 검색 및
   원본 열기를 확인합니다. 참가자 역할은 허용, 제한 역할은 지정 콘텐츠를
   발견하거나 열 수 없어야 합니다. 화면에는 민감한 제목을 노출하지 않습니다.

> “검색 결과는 계정 권한에 따라 달라집니다. 파일이 존재하는 것과 이 사용자가
> 검색하고 열 수 있는 것은 서로 다른 검증입니다.”

킥오프 로그에는 팀, Ontology ID, 성공 개수, 실패 키워드, 정규화·권한·범위
조치를 기록합니다. 메타데이터의 `businessDate`와 실제 M365 생성·수정·게시
시각은 다를 수 있습니다. 실제 배포 시각을 과거 업무 시각으로 위조하지 않습니다.

### 미션 2 — 엔터티와 문서를 연결 (25분)

공통 Q2의 `배송` 또는 `LateDelivery`를 검색하고 승인된 샘플의 배송 지연·CS
관련 Teams 대화와 SharePoint 운영 문서, Outlook 반품 요약을 열어 비교합니다.
다음으로 `AeroPhone X` 검색 결과에서 Teams 대화와 Outlook 회신을 비교하고
`SummerPush` 기획서와 성과 리포트도 보여줍니다. 이 검색이 실제 제품의 단일
고정 UI를 전제하지 않도록 출처 필터와 결과 화면은 준비된 커넥터에 맞춥니다.

> “같은 상품이지만 배송팀과 결제팀은 서로 다른 사건을 말합니다. 문서가 있다는
> 사실은 연결 근거이지 그 자체가 정형 KPI나 원인 확정은 아닙니다.”

매핑표에 엔터티 유형·값, 제목, 소스, 원본 링크/ID, 정확/부분/실패, 비고를
기록합니다. 캠페인 4개, 상품 5개, 고객등급 1개에 각 1건 이상, 총 유효 매핑
10건 이상을 확인합니다. `AeroPhone X`, `SmartWatch Pro`, `UltraBook 15`는
재고/배송/CS 관련 콘텐츠 각 2건 이상입니다. `Aero Phone X`처럼 다른 표기
1건과 정규화 방법을 남깁니다.

실제 검토한 매핑 CSV는 **저장소 밖의 승인된 접근 제한 경로**에 보관합니다.
아래 예시 경로는 실제 승인된 경로로 바꾸고, 화면 공유 시 내부 URL과 파일
내용·주소 표시줄을 가립니다. 검증기는 ACL이나 live 접근을 대신 확인하지
않습니다. manifest 일치까지 필수로 판정하려면 다음처럼 옵션을 지정합니다.

```bash
python3 track2/data/verify_entity_document_mapping.py --mapping-csv "/approved/restricted/path/mapping_result.csv" --manifest-csv ./track2/data/generated/manifests/content_manifest.csv --require-manifest-match
```

경로는 예시이며 사전에 파일을 준비해야 합니다. 정적 manifest와의 일치는
실제 검색·원본 접근·ACL PASS의 증거가 아닙니다.

### 미션 3 — 근거의 품질을 질문하기 (35분)

각 항목에 실제 확인한 증적을 붙입니다. 화면에는 샘플 내용만 보여줍니다.

| 항목 | 발표자가 보여줄 확인 |
|---|---|
| 정확성 | 문서 날짜·채널·수치를 Fabric의 해당 테이블/컬럼과 대조 |
| 완전성 | 엔터티별 매핑 커버리지와 빠진 문서 |
| 일관성 | 같은 이름의 공백·별칭 차이와 정규화 |
| 유효성 | Draft/Final 및 게시·보관 상태가 목적에 적절한지 |
| 중복성 | 동일 주제의 버전·사본 링크 2건 비교 |
| 참조무결성 | 문서 내부 참조 링크 열기와 실패 기록 |
| 적시성 | 업무 기준일과 실제 수정일, 보존 정책 구분 |
| 추적성 | 검색 결과에서 원본으로 이동 가능 여부 |

> “관련 문서를 찾았더라도 초안인지, 오래됐는지, 원본을 열 수 있는지 따져야
> 인용할 수 있습니다. 증거가 부족하면 높은 점수를 추정하지 않습니다.”

정형 측면은 Track1에서 확인된 기준값과 제한을 참고합니다. P1 오류 위치·건수
탐지는 별도 과제로 만들지 않습니다.

### 미션 4 — 점수와 Track3 인계 (25분)

8항목 각각 `0/25/50/75/100`으로 채점하고 근거와 미달 조치를 표시합니다.
75 이상이 PASS, **8개 중 6개 이상 PASS**가 품질 게이트입니다. 평균은 8개 점수의
산술 평균이지만 평균만으로 통과를 판단하지 않습니다. 미충족이면 최소 2개
조치안을 기록하고 정상 완료로 선언하지 않습니다.

> “점수의 목적은 숫자를 예쁘게 만드는 것이 아니라, 어떤 근거가 다음 단계에
> 안전하게 전달될 수 있는지 드러내는 것입니다.”

발표자가 승인된 증적 보관 위치에 아래 형식으로 완성합니다. 미검증 링크를 채워
완료처럼 보이게 하지 않습니다.

```text
[TRACK3_WEBIQ_HANDOFF_PACKAGE]
team=<팀명>
handoffAtKst=<YYYY-MM-DD HH:MM>
indexCatalogRef=<경로/문서>
qualityScoreSummary=<정확성:점수, ...>
failedQualityItems=<항목1;항목2 또는 ->
evidenceLinks=<URL1;URL2;URL3;URL4;URL5>
priorityIssues=<이슈1|영향|임시조치; 이슈2|영향|임시조치; 이슈3|영향|임시조치>
reproQueries=<질의1;질의2;질의3>
[/TRACK3_WEBIQ_HANDOFF_PACKAGE]
```

유효한 **내부 링크 5개 이상**, 우선 이슈 Top3, 재현 질의 3개와 8개 점수·미달
항목이 필요합니다. 이 패키지는 먼저 [Track3 WebIQ](../track3/WORKBOOK.md)가
받습니다. Track3는 내부 근거와 별도로 공개 citation을 검토한 후 Track4
FoundryIQ에 인계합니다. 내부 URL·고객명·주문번호·미공개 수치를 웹 검색어에
넣지 않습니다.

## 검증, 장애와 복구

| 상황 | 조치와 발표 판정 |
|---|---|
| 인계 누락 | Track1에 보정 요청. 5분 내 미보정 시 임시 설명만 하고 blocking issue 기록 |
| 검색 0건/4개 미달 | 권한 → 색인 범위 → 표기 점검·재시도. 10분 넘으면 승인된 캡처/시드 명세로 전환하고 live 검색 성공이나 게이트 통과라고 하지 않음 |
| 소스 하나만 실패 | 관리자에게 권한·범위·색인 확인 요청. 제한적 사용으로 기록하고 4소스 완료는 보류 |
| ACL 결과가 예상과 다름 | 즉시 화면 공유 중지, 접근 노출 기록 및 관리자에게 수정 요청. 샘플이라도 ACL PASS로 표시하지 않음 |
