# Microsoft IQ 산업별 대표 활용 시나리오

> 대상: Microsoft IQ 워크숍 참가자
> 용도: 산업별 대표 활용 사례를 빠르게 비교하고, 관심 있는 상세 시나리오로 이동하는 요약 카탈로그

Microsoft IQ는 내부 정형 지표(FabricIQ), 권한이 적용된 업무 근거(WorkIQ),
공개 웹 근거(WebIQ)를 분리해 수집하고 FoundryIQ에서 대조·평가합니다.
최종 조치는 항상 사람의 승인과 조직의 SOP를 거칩니다.

## 공통 적용 원칙

1. **FabricIQ**는 내부 정형 데이터의 KPI, 기준선, Ontology 관계 경로를 검증합니다.
2. **WorkIQ**는 ACL이 적용된 Microsoft 365 문서·대화에서 결정, 담당자, 예외와 진행 상황을 확인합니다.
3. **WebIQ**는 민감정보 없는 검색으로 공개된 최신 상황을 확인하며, 내부 원인을 단정하지 않습니다.
4. **FoundryIQ**는 권위 SOP·정책과 세 근거를 대조하고, 미확인 사항과 승인 필요 조치를 분리해 문장화합니다.
5. `simulation`은 고정 샘플로 재현하는 검증 모드이며 실제 운영 결과나 현재 웹 사실을 증명하지 않습니다.

## 상세 시나리오 읽기

각 상세 문서는 업무 범위, 탐지 신호와 질문, FabricIQ·WorkIQ·WebIQ·FoundryIQ의 역할,
사람 승인 경계, 완료 기준을 포함합니다. 실제 PoC에서는 먼저 한 지역·사업부·서비스로
범위를 좁히고, 기준선·권한·SOP 버전을 승인한 뒤 `dry-run`과 `simulation`을 거쳐
승인된 환경에서만 `live`로 전환합니다.

공통 워크숍 일정과 트랙 간 인계 계약은
[Microsoft IQ 워크숍 통합 계획](../common/docs/Microsoft_IQ_Workshop_Integrated_Plan.md)을
참조합니다.
